# rebalancer

The compute half of compute-then-validate. Anyone can call `rebalance`; it reads the current price for both assets from a Reflector oracle, decides whether a rebalance is worth doing at all, computes the exact trade size and swap if so, and calls Soroswap's router requiring the target smart account's authorization. There is no caller-supplied trade size: a permissionless caller identifies the account and the rule, never how much moves. The account's `rebalance-policy` contract is what actually decides whether the finished swap is allowed, and does not change based on how the price or size were computed, since it only ever sees the finished swap arguments (plus its own independent cooldown check).

## Pricing and the safe default

Prices come from a Reflector oracle's `lastprice()`, read by ticker symbol (Reflector prices assets by symbol, not by contract address) for both the sell and buy asset. If either price is missing, or the most recent price is older than 600 seconds (twice Reflector's own 300 second update resolution), `rebalance` refuses outright: no swap is attempted, and there is no fallback price.

`amount_out_min` is computed from the oracle price and the target account's own `slippage_tolerance_bps` (read from its installed `rebalance-policy` rule), adjusted for each token's own decimals. The tolerance is not decided here: it is a per-user setting the policy contract owns and range-checks, and the policy independently rederives the same floor from its own oracle read before approving the swap, rather than trusting this contract's math.

## The over-trading gate and target-driven sizing

`rebalance` reads the account's live balances of both assets and its installed rule's `target_buy_weight_bps`, and refuses (`BelowBand`) unless the resulting drift exceeds `band_threshold_bps`. If it does, it computes the exact trade value that would close the drift, sizes it in `sell_asset` terms against the oracle price, then queries the router's own `router_get_amounts_out` for that candidate size and scales the trade down if the pool's real quote implies more value than the oracle did. The result is checked against `min_trade_size` (`BelowMinTradeSize`) and a cost-versus-benefit gate comparing the trade's estimated cost (Soroswap's fee, plus `slippage_tolerance_bps`, plus a `reserved_tip_bps` allowance for a not-yet-built future tip) against `max_cost_ratio_bps` (`CostExceedsBenefit`). After the swap, `rebalance` checks the real result against the account's target, reverting the whole transaction (`OvershootTolerance`) if it landed more than a small bounded tolerance past it. The stated guarantee is bounded overshoot within tolerance, not an exact landing: a real, on-chain testnet finding showed sizing against the oracle price alone could overshoot, which is why the pool quote and the post-swap check both exist.
